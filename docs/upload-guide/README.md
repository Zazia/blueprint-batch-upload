正文源文件为 [usage-walkthrough.md](../usage-walkthrough.md)，面向设计院设计师，适用广州市审图系统。文章依次讲痛点、技能设计理由、八个情境处理方案和作者的体验邀请。打开 [index.html](index.html) 看图文预览，[body.html](body.html) 为独立的行内样式正文。当前标题为“广州审图系统太难用了，我给上传图纸写了个技能”。

## 图片规格与内容

第二版恢复矩形操作节点、菱形判断、有标签的分支箭头和阶段分组。十张 PNG 统一宽度 840px，按 2 倍清晰度输出；文章显示宽度上限为 420px。图中节点文字在该显示宽度下为 14px，分组标注 14px，分支标签 12px，略小于文章 16px 正文。小屏按容器等比缩放；不把较简单的图单独放大。图片高度随实际流程变化，不再强制统一 3:4 或用四张文字卡片代替流程图。

总体流程将“形成报告”和“授权提交”合并为一个展示阶段，执行逻辑未改变。箭头表示真实处理路径，判断分支明确标注条件。流程内可以停止某一待核查项，其他独立明确项继续。接口图中的未来识别衔接用虚线表达，不表示现有实现。

## 编辑与重新生成

[diagrams.cjs](diagrams.cjs) 是十张图的节点、分组和边的统一来源；[render-flow.cjs](render-flow.cjs) 控制窄幅布局、节点形状、连线与字号；[build.cjs](build.cjs) 生成 PNG、SVG、Mermaid、DOT 源、正文 HTML 和本地预览。图源在 sources/。发布使用 PNG，无需公众号支持 SVG 或 Mermaid。

复用已安装的 Node.js、Playwright 和 Chrome。将 NODE_PATH 指向实际包目录，CHROME_PATH 可指定浏览器可执行文件，不需要新下载绘图库：

```powershell
$env:NODE_PATH = '<已安装依赖>/node_modules'
$env:CHROME_PATH = '<Chrome 可执行文件路径>'
node docs/upload-guide/build.cjs
```

如果改文案，先改 Markdown 与 diagrams.cjs 中对应内容，再生成；添加节点时同步修改 render-flow.cjs 中的行布局。不要单独编辑生成的 PNG。Python 环境仍遵循项目指南，安利使用 uv；本制图步骤只使用 Node.js。

生成程序逐张检查节点文字及全部文本的画布边界，并固定图片宽度和字号；结果在 [validation.json](validation.json)。流程图已作代表图目视检查，不对微信公众号实际粘贴效果作已验证声明。

## 公众号使用

推荐打开 index.html，点击“复制正文”，粘贴到公众号图文编辑器；随后把 assets/ 中对应 PNG 上传并替换正文里的本地图片，再检查手机预览。复制按钮依赖浏览器能力，失败时选中正文后按 Ctrl+C。本地路径不会变成公众号已托管的图片。

如更习惯 Word，可后续另行导出 DOCX 并使用公众号后台支持的导入方式。本轮不生成 Word、不连接公众号 API、不代发布。

结尾保留了用户提供的旧文经历与“阅读原文”下载邀请。发布前需由作者设置真实下载地址，目前尚未提供链接，稿件不生成虚构下载按钮或网址。

制作时已使用公众号技能建立文章目录。其注入命令在当前 Windows 环境退出码为 1 且无诊断，遂采用本项目生成器输出独立预览，未读取或修改技能模板脚本。正文仍遵循单列、行内样式和 PNG 插图约定。
