## 真实材料测试后的首次上传修正（2026-10-14）

用户提供真实本地材料测试，随后确认“还没有系统目录，按首次上传”。测试转为初次上传离线预检，不作为棕地系统建档或在线上传成功。真实材料、清单及测试报告仅保存在忽略的 .work 路径，不提交仓库。

真实 PDF 测试发现：计划中 action=add 的非 PACK 文件被统一覆盖为 native-target，错误指向已有图纸入口。修正方案：所有新增成品保持 native-add；仅已有记录的非 PACK 新版/取消材料走 native-target，保留原生类型和验章校验。先补新增 PDF/GDB 与已有 PDF 更新的回归用例，再修正分流。

同一来源分组内规划、跨分组目录重号拦截及副本外层改名均已测试。来源分组只是离线测试范围，不等于真实系统单体；目录同号是否需要调整仍取决于实际系统范围。未修改原设计文档。

验证结果：新增用例先复现错误，修复后完整 Python 回归 23 项通过。真实文件按独立测试范围规划的新增项均正确选择 native-add；合并范围中的同号目录仍被拦截。原文件集合与 SHA-256 前后核对一致，仅对测试副本执行改名。
