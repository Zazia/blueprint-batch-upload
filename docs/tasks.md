## 3. 行为验收场景

以下是后续验收定义，本轮没有执行在线测试。原技能既有竣工实测是经验基线，新实现验证其保留情况及新增能力，不把所有经验重新降为待研究假设。

| 用例 | 场景 | 预期结果 | 需求 |
|---|---|---|---|
| V01 | 给出普通初次上传目录 | 格式/命名预检后批量建目录及首版，核对后完成上传 | R01、R02、R04、R09 |
| V02 | 初次图号含点，且点转连字符会重名 | 在上传前提示并解决冲突，不盲目替换；不误改扩展名的点 | R02、R03 |
| V03 | 只改 PACK 外层名但内图签仍为旧号 | 明示映射或内容不一致，不能宣称包内图号已改变 | R02、R03、R10 |
| V04 | 系统已有含点图号 | 保留系统图号，对应新版走路径 B，不强改系统编号 | R03、R05–R07 |
| V05 | 已有目录无点与含点混合 | 先 A 后 B，核对同一任务范围后完成上传 | R05–R07、R09 |
| V06 | 同图号跨单体/单位/专业或范围内多候选 | 限定上下文；歧义不取首项，不错挂记录 | R01、R05、R06 |
| V07 | 系统录错图号但能明确对应成品 | 按系统图号直接改成品名并上传原记录，映射可追溯 | R03、R05、R06 |
| V08 | 成品直接改名遇重名或环形交换 | 不覆盖，内容不变，完整记录改名映射 | R03 |
| V09 | 一般/重大变更已推送设计单位 | 同一对应新版流程，完成上传即结束本技能，不发起或判定变更 | R05、R09 |
| V10 | 变更文件找不到原图记录 | 列出未匹配项，不自动新增目录 | R05 |
| V11 | BGID 非空，无变更新版且无竣工版 | 必须列入竣工待上传清单，无变更版不是豁免理由 | R06 |
| V12 | 曾勾选图已有可确认有效竣工版，无新文件 | 计入已满足，恢复时不重复上传 | R06、R08 |
| V13 | 曾勾选图缺少本地成品 | 输出具体缺文件；不清 BGID、不减少应传集合、不宣称完成 | R06、R09 |
| V14 | BGID/版本响应缺失、分页未采全或专业晚到 | 标记集合不完整，不当成无缺项；响应绑定原上下文 | R01、R06 |
| V15 | 用户目录文件都传完，但其他必传图仍缺竣工版 | 差集检出缺项，完成上传受阻不能报成功 | R06、R09 |
| V16 | 文件请求 200，但保存失败或解压失败 | 不计成功，按保存/解压环节定位 | R08 |
| V17 | 页面超时/刷新，服务器可能已经保存 | 回读后恢复，已有版本/初次目录不重复建立 | R04、R08 |
| V18 | 合法 PDF 直接上传 | 保留真实扩展名和校验，不伪装 PACK | R02、R07 |
| V19 | 文件核验完成且用户委托完整上传 | 继续完成上传并回读，不默认停在文件传完或再次请求同一授权 | R09 |
| V20 | 用户明确只试传/部分上传/先不提交 | 执行限定范围，不误点结束整批任务的按钮 | R01、R09 |
| V21 | 收尾返回错误或状态未确认 | 报告“文件已上传，完成上传受阻/待核实”，不能报任务完成 | R09 |
| V22 | 只有成品目录，没有准备技能清单 | 可以预检、匹配、改名、上传，不要求先安装准备技能 | R10 |
| V23 | 接收文件名含父级路径、盘符或重复名称 | 拒绝越界，保留前次证据，不覆盖其他运行 | R08 |
| V24 | 所有计划项结束，包含缺件、失败、未知 | 数量与计划一致，文件结果和完成上传结果分别列明 | R08、R09 |

## 4. 验收组织

离线先验证文件命名、对应、改名与差集；页面样本验证状态和恢复；有获准执行范围时验证新增入口与三个上传收尾节点。保留原技能的竣工实测结论，不把未执行的新测试写成已通过。完整任务成功必须包含对应范围“完成上传”成功；仅文件上传能力验证通过，不能宣称任务闭环已完成。
