## 3. 行为验收场景

以下是未来验证用例定义，不是本轮已运行的测试。离线用例用合成或脱敏文件；在线写操作只在获准工程及范围执行。验证真实行为和状态，不用“文案包含某关键词”代替验收。

| 用例 | 场景 | 预期结果 | 对应需求 |
|---|---|---|---|
| V01 | 用户只要求导出清单 | 产出快照和完整性信息，无上传/提交请求 | R01 |
| V02 | 同图号出现在不同单位、单体或专业 | 精确限定目标，不全局取首项 | R01、R03 |
| V03 | 同范围两个候选、相似名称 0.8 分 | 标为待复核，分数不构成自动确认 | R02 |
| V04 | 本地文件名含中文、多个点、下划线及百分号 | 无截断或重复 URL 解码；原始名称保存，解析歧义可见 | R02、R03 |
| V05 | 暂存改名遇到重名或原地改名环 | 不覆盖文件；暂存哈希等于原件；如原地执行可核对恢复 | R02 |
| V06 | 普通图纸缺 CAD，另有合法无 CAD 报告 | 前者缺项，后者走实际 PDF 分支，不统一伪装 PACK | R02、R03 |
| V07 | PACK 合法性校验失败 | 不进入上传集合，保留工具结果 | R02 |
| V08 | 文件无对应记录但用户只要求上传新版 | 留待核查，不自动新增目录 | R03、R04 |
| V09 | COS 成功、版本保存业务失败但 HTTP 200 | 不报成功；记录存储与版本结果差异 | R03 |
| V10 | 版本保存成功、解压失败或迟到 | 保持未核验，禁止计入 verified；后续回读处理 | R03、R09 |
| V11 | 服务器已保存但页面超时/刷新 | 本地留 unknown，恢复回读后跳过重传 | R03、R09 |
| V12 | 同阶段上传返回相同版本号但新 VSID | 按真实记录核验，不强求版本数加一 | R03 |
| V13 | 批次中切专业、会话过期或启动第二批 | 暂停/拒绝冲突，保留已发任务的待核查状态 | R03 |
| V14 | 采集时上一专业响应晚到或页面有分页 | 快照按请求归属，不误标专业；不完整采集明确显示 | R01 |
| V15 | 一般变更仅有联系单和关联图纸 | 不强制上传新版；材料与关联须完整 | R05 |
| V16 | 重大变更图纸均上传成功，流程为待审查 | 只报上传节点完成，不报已完成变更 | R06 |
| V17 | 整改图已上传但意见回复未提交 | 分别报告，不把两者混作完成 | R07 |
| V18 | BGID 非空、无变更版，但存在一般变更记录单 | 不能判为误圈；查实际变更及竣工成果 | R08、R09 |
| V19 | 历史项目需整套补传，本地少一个专业 | 完整目录对账发现缺项，不以当前文件全部成功作为整套完成 | R08、R10 |
| V20 | 初次新增、历史补工程、缺专业补录 | 各自识别入口与前置，不复用“上传新版”错误动作 | R04、R10 |
| V21 | 接收路径含 `..`、反斜杠、盘符或超大/非 JSON 内容 | 拒绝请求；证据目录外无写入，前次结果不覆盖 | R01、R09 |
| V22 | 用户只要求上传，但页面可通知确认/签章/完成编制 | 报告后续动作，未授权部分不执行 | R03、R08 |
| V23 | 所有任务执行结束，含失败/未知/跳过 | 各状态合计等于计划总数，每项具备明确结果 | R03、R09 |
| V24 | 页面函数签名或响应结构发生变化 | 能力检查失败即停用该适配，保留原生/人工方式 | R03–R10 |

## 4. 最小上线门槛

P0 公共上传能力至少通过 V01–V14、V21–V24；业务路由至少通过 V15–V19、V22。新增/整改/补录能力各自满足 V17、V20 后才能在描述中声明支持自动执行。静态代码检查、技能格式验证不能替代这些行为验收。无在线验证条件时明确标为离线可用或待实测，不以历史案例代替当前结果。
