# 场景介绍的新媒体改写与制图方案

2026-10-27。范围为说明文档和发布素材，不改变上传技能行为。

## 需求与设计

将 usage-walkthrough.md 改写为面向设计单位的公众号文章。开头从点号重号、竣工缺图、上传后解压失败等具体体验切入，使用说明性情境，不编造亲历事故、耗时收益或在线验收。选取八种有说服力的用户请求，每段主体说明技能如何分阶段处理、分支如何决定以及交付什么。

保留当前匹配边界、包外改名、增补/取消及目录规则、竣工必传经验、恢复去重、提交确认和报告口径。两个接口仍只预留。实现细节链接操作参考，不塞进宣传正文。

流程图统一为 1080×1440 的竖图。每图四个编号阶段容器，粗看标题能把握全程，细看容器内部理解条件与动作。统一字号和间距，不用缩字塞内容。提供 PNG 发布图、SVG 可编辑源图和分阶段 Mermaid 文本源。总体图、八个情境图及接口图共十张；主文章使用前九张，接口图在接口文档引用。

## 任务与计划

1. 编写文章及结构化图表内容，保持文字与图一致。
2. 以同一数据源生成阶段分组图、PNG、Mermaid 源及行内样式正文 HTML；不依赖在线绘图服务。
3. 如公众号技能模板脚本在当前 Windows 环境可运行则复用；运行环境不兼容或脚本失败时，在现有仓库制作可直接打开的本地预览与独立正文 HTML，不为模板改造环境。
4. 检查全部图片尺寸、字体溢出、阶段完整性和文档链接，目视检查代表图片。图片导出通过本地浏览器完成，公众号正文不进行浏览器截图验收；不宣称通过微信后台粘贴验证。
5. 更新实施记录，Git 单独提交文案与素材。保留业务代码与原冻结设计。

## 交付与验收

- 正文含具体痛点、八个情境、分阶段处理说明和完成报告示例。
- 十张图全部同尺寸、同字号、纵向阶段分组，适合单独保存及后续贴图编排。
- Markdown、正文 HTML、预览及图片路径齐全；有生成源便于后续统一改图。
- 不读取或修改真实图纸，不操作审图系统，不发布到公众号。
