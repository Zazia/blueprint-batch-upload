# 准备图纸技能预留设计

日期：2026-10-09｜预留稿 v0.2｜衔接上传设计 v0.3，尚未创建或实施。

## 1. 定位与交付

面向设计单位，将源 CAD/PDF 整理为可交付上传技能的成品文件。覆盖源文件规范命名、图纸拆分、CAD/PDF 配对、打包和验证；交付成品目录、可选材料清单以及未完成项。后续单独设计和实现，不阻塞上传技能使用用户已准备好的文件。

建议技能名暂记 `prepare-blueprints`，最终名称在创建时确定。本轮只保留本设计文档，不初始化新技能或安装任何工具。

## 2. 输入与输出

输入：源图目录、图纸目录或编号规则、专业/单体归属、CAD/PDF 已拆分情况、所需成品类型，以及可选的既有系统目录。

输出：按单体/专业组织的成品目录（PACK、允许直接上传的 PDF 等），`prepared-manifest.json`（可选）、缺项/冲突/校验报告。原图默认保留，拆分和打包输出到明确的成品位置。

可选清单拟用以下字段：

| 字段 | 含义 |
|---|---|
| schemaVersion、preparedAt | 清单版本及生成时间 |
| artifacts[].id | 本地成品标识 |
| artifacts[].unit、profession | 单体、专业 |
| artifacts[].drawingCode、drawingName | 源图号与图名 |
| artifacts[].path、type、size、sha256 | 成品文件身份 |
| artifacts[].sourceFiles | 源 CAD/PDF 与拆分来源 |
| artifacts[].validation | 配对、包验证、内容检查的结果和未检查项 |
| artifacts[].uploadAlias | 若采用外层上传别名，记录别名及对应关系 |
| issues[] | 缺 CAD/PDF、重复图号、无法拆分、非法包等问题 |

上传技能不强制要求清单。清单已有时保留其源图信息，并另记实际上传名。上传阶段默认不读取、检查或同步更正包内图号、图签及目录；直接改外层包名，不因外层改名要求返回准备阶段同步内容。

## 3. 任务流程

### 3.1 文件盘点与命名

识别单体/专业、源图号/图名、文件类型、重复及缺失。初次上传材料尽早采用系统友好的图号，尽量不使用点，避免后续只能逐条上传；明确点号的替代规则并检查碰撞，例如 `A-1.1` 与已有 `A-1-1` 不能改成同一名称。

源图命名需考虑 CAD/PDF、图签、目录和成品之间的对应关系。已有项目沿用正式编号，不为统一风格擅改已上系统的图号。上传阶段为了匹配系统旧记录进行外层改名，由上传技能完成。

### 3.2 拆分

根据源材料选择 CAD 拆图/打印或 PDF 分页拆分。优先复用设计院已有工具或系统提供的 CAD 辅助工具，不自行重造 CAD 拆图引擎。明确布局空间、图框、比例、方向和多页材料的处理方法；具体自动化程度待后续实际样本设计。

需要用户在专业 CAD 软件中完成的步骤，给出清楚的操作范围和输出要求。单纯拆分不包含专业设计修改或重新绘制竣工成果。

### 3.3 配对与格式检查

CAD/PDF 一一对应，名称和图纸内容一致；按资料要求关注 T3、字体及图纸可见内容。文件同名不等于内容相同，分别记录自动检查、视觉核查和未核查项。允许仅 PDF 的专篇/报告按真实材料类别处理，不靠改名绕过格式限制。

### 3.4 打包与验证

复用 `D:\00-审图系统\ZwPack` 中已有工具，打包匹配的 CAD/PDF，并用工具的目录或单文件验证功能检查。当前仅确认工具存在，尚未确认 CLI 能力；若 GUI 一次选目录即可完成，保留该直接方式。不能只把 ZIP/PDF 改后缀作为 PACK，也不自行仿制包格式。

成品完成后记录数量、大小、哈希及验证结果。非法包或配对缺项进入报告，不混入已完成集合。

## 4. 与上传技能的职责约定

| 情况 | 处理方 |
|---|---|
| 需要修改图内图号、拆分范围、CAD/PDF 内容或重打包 | 准备图纸技能 |
| 已打包文件需按本次初次上传命名规则改外层名 | 上传技能可直接处理 |
| 变更/竣工需要与已有系统图号对齐 | 上传技能直接改成品名，保留映射 |
| 系统拒绝包文件/解压失败，或缺少对应成品 | 上传技能报告系统结果或缺项，准备阶段按需要补齐；上传端不额外读取包内 |
| 增补/取消导致新版正式目录或取消变更单缺失 | 上传技能提醒缺件；用户或准备阶段提供成品，不用机器账本替代 |
| 上传、解压核验、完成上传 | 上传技能 |

两个技能通过文件和清单衔接，不要求常驻服务、共享数据库或互相自动调用。上传技能的成品改名不应反向触发不必要的拆分或重打包。

上传技能负责 [长期目录与改名表](catalog-management-design.md)。准备阶段可读取导出的命名映射，使后续成品沿用目标包名；未应用映射也不影响交付，上传技能会对同范围同图名重放相同改名。图纸目录文件与取消变更单属于正式材料，其编制内容不由上传技能自动生成。

## 5. 后续独立设计任务

1. 用真实 CAD/PDF 样本确定拆分工具、命名规则和内容核查方式。
2. 确定 ZwPack 的可调用方式及批量验证结果的读取方式。
3. 明确成品目录和清单格式，保持无清单也可交付的简便路径。
4. 验证重复图号、点号替换碰撞、CAD/PDF 缺配对、图内外编号不一致、非法包及已完成项续做。

验收以“输出文件可由上传技能使用”为终点，不执行系统上传。本技能的实施任务不并入当前上传技能实施计划。
