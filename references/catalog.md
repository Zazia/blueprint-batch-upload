# 项目目录与长期映射

不重排源文件夹。每次以系统最新列表为准，项目资料目录保留长期映射、系统观察结果和运行证据。三个对象不同：系统列表决定目标 BPID；用户提供的正式目录是上传材料；本地机器账本只辅助对应和恢复。

## 初次与棕地

用实际站点/WID/OrgId 选独立的项目资料目录，单体/专业作为行作用域。已存在映射时加载；首次接手没有本地记录，就从系统快照 `sync` 建立基线，不重传旧图、不进行历史补录、不伪造曾经的操作。

列表采集范围不全标 complete=false；缺 BGID 或版本字段不能填 null/[] 假装已知。系统快照包含的行更新账本，缺席行保留，不能由一部分文件/一次分页推断删除。每次 sync 返回已观察行的变化 BPID；有外部变动时重新核对受影响计划。

目录 PACK 不打开，只记录它的文件和系统版本。独立可读目录清单可以对账；没有清单就写“未解析目录内容”，不因此给用户增加拆包工作。

## 映射复用

`aliases.json` 按单体、专业、图名保存原图号、上传图号、文件名、BPID 及来源 runId。全项目再由 catalog 的站点/WID/OrgId 隔离。新版内容哈希变化不应使映射失效。

例：首次 `A-1.1_首层平面图.pack` → `A-1-1_首层平面图.pack`；下次相同范围同图名使用同一上传名更新原图。其他单体同名图不能套用。同名多图或映射在当前系统不见了需消歧，不能自动建立重复记录。

`rename` 原地两阶段改名并保留日志，支持目标互换、重跑和中断恢复，不覆盖无关文件。取消单服务多个图时保持原文件名，通过原生目标上传/临时 File 名称处理，不对同一源文件尝试多重改名。已改名但尚未上传的映射会保留 applied 状态；同次任务继续原 runId，上传后的映射才绑定 verified 结果。

## 增补和取消

使用请求清单显式 action=add/cancel。目录材料 kind=directory，`directoryFor` 列出它覆盖的受影响 BPID（已有图）或原图号（新增图）；这是用户材料范围声明，不是 PACK 内容解析结果。缺覆盖对应项的新版目录则提醒，不能拿本地生成的 CSV 代替。

取消材料 kind=cancellation，指定原 BPID，保留版本链。一份材料可有多个明确目标，以每图的上传结果计数。仅匹配失败不是新增，仅本次没文件不是取消。

## 保存与恢复

`catalog.json` 保存当前观察及已提交状态，`aliases.json` 保存映射，`snapshots/` 保存观察来源，`runs/<runId>/` 保存计划、改名日志及逐次回执，`revisions/` 保存成功收尾时的目录修订。运行资料不进技能 Git。

先记录服务器已发生事实；只有完成上传成功才记录 submitted 修订/取消已提交状态。收尾失败保留已上传项，先重新回读再续做。不要删除运行目录来“重新开始”。项目 `.upload.lock` 存在时禁止并发本地写入；只有确认无在跑进程，并检查改名临时文件/日志后，才能处理崩溃遗留锁。

工具不发系统网络请求，也不能从一份人造 JSON 证明服务器成功。真实采集、文件处理、页面动作和回执证据由代理按本技能执行，数据记录工具负责检查一致性。
